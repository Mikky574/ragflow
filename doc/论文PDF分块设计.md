# 论文 PDF 分块设计

## 目标

让用户的问题先命中一个主题明确、噪声少的文本块；该块本身应包含回答问题所需的主体、条件、对象、单位和结论。对于需要更多上下文的问题，检索结果应能自然带出相邻正文或所属章节，而不是依赖图内 OCR 或跨栏拼接的文字。

分块的质量以问答效果衡量，不以块数越少或 token 越大为目标。一个合格块应只承载一个紧密相关的论述单元，例如：一个方法步骤、一个实验设置、一组结果及其解释，或一个结论。

## 适用范围

适用于双栏英文技术论文、会议论文和期刊 PDF。它们常含有跨栏阅读顺序、图表、图注、页眉页脚和图内文字，不能假设版面顺序等同于语义顺序。

## 推荐的基线配置

先以独立文本块作为检索基线，便于审阅和定位解析问题。

| 项目 | 建议值 | 原因 |
| --- | --- | --- |
| 解析器 | Paper | 保留论文标题、章节和 PDF 位置信息。 |
| 单块上限 | 500–600 token | 足以保留一个完整论述，同时避免检索向量被多个主题稀释。 |
| 重叠 | 5–10% | 只保护段落边界的上下文，避免大量重复。 |
| 父子分块 | 默认关闭 | 块列表干净，不产生母块与子块的重复记录。 |
| 表格上下文 | 1 | 给表格保留一小段邻近说明。 |
| 图片上下文 | 0 | 图内 OCR 噪声较多时，不把它扩散到正文块。 |
| 图、表和图注 | 独立审阅 | 图文关联由版面解析决定，不能仅靠 token 上限解决。 |

当前文献可先使用 `550 token`、`0.08` 重叠作为起点。设置保存后必须重新解析，旧索引不会自动应用新配置。

## 块应具有的内容

正文块应尽量满足以下条件：

1. 开头保留章节标题或足够的主语，避免出现无指代的“this method”“the result”。
2. 方法块同时保留对象、关键参数和步骤。
3. 结果块同时保留测量条件、数值、单位和比较对象。
4. 结论块保留结论和适用条件。
5. 标题、作者、单位和摘要至少应有一个可检索块；它们不应被页眉、版权声明或图内 OCR 淹没。
6. 图表问题至少应检索到图注；若图片本体无法可靠关联图注，图表应作为单独的检索对象，而不是和无关正文强行合并。

## 不应出现的内容

- 两栏文字交错拼接成一个句子。
- 单独的坐标轴、图例、扫描参数或乱码成为主要正文块。
- 只有“Fig. 2 shows …”而没有图号、图注或相关说明的孤立引用。
- 相同正文因大重叠或父子块展示而反复出现。
- 一个块同时包含多个章节、多个实验或多个互不相关的图表。

## 父子分块的使用条件

父子分块适合正文很长、问题通常只命中其中一小段、回答却需要整段上下文的资料。它会存储可检索的子块和不可检索的母块，因此块列表中会看到内容重叠，记录总数也会增加。

启用前应先确认独立块的阅读顺序和图文质量已经合格。对于本类短论文，先关闭父子分块建立基线；只有出现“能命中相关句，但回答缺少前提或结论”的问题时，再启用它。

若启用，建议如下：

| 项目 | 建议值 |
| --- | --- |
| 母块上限 | 700–900 token |
| 子块分隔 | 段落空行（`\n\n`） |
| 子块目标 | 180–350 token，保留完整段落 |
| 禁止的子块分隔 | 单个换行（`\n`） |

单个换行在 OCR PDF 中通常等于视觉换行，会把一段正文切成很多碎片。

## 调参顺序

1. 先审阅标题、摘要、引言、一个方法段、一个结果段、一个图表页和结论页。
2. 阅读顺序错误时，优先更换或改善解析方式；不要先增加 token 上限。
3. 块包含两个以上主题时，降低上限 50–100 token，或按章节/段落切。
4. 块缺少结论或实验条件时，增加 50–100 token 或将重叠提高到 10%。
5. 图内 OCR 噪声影响检索时，保持图片上下文为 0，并核验图注是否独立可检索。
6. 只有在正文块已干净、但回答仍缺上下文时，才启用父子分块。

## 本文献的验收目标

- 正文检索块以约 200–550 token 为主，极少超过 600 token。
- 查询“Doherty amplifier 的效率”“WCDMA 下的 ACLR”“class-F PA 的参数”“论文结论”时，前几条结果应包含完整可读的相关段落。
- 查询 “Fig. 2” 时，至少一条结果含 `Fig. 2. Full schematic ...` 图注；图内 OCR 不能排在其前面。
- 标题与作者信息可被检索到，且不和正文中段混在一起。
- 审阅列表中不存在由重叠造成的大量近似重复块。
